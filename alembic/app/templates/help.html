Help & Examples

Quick pointers for working with self-signed certificates while we build the interactive tools.

What is a self-signed certificate?

A self-signed certificate is signed by the same entity that creates it rather than a public Certificate Authority. They are great for lab, QA, or demo environments where you just need TLS quickly.

Browsers will warn users because the issuing authority is not trusted by default, but installing the certificate into your local trust store or device keychain removes most prompts.

How to use this with localhost

Pair the generated certificate/key with your preferred reverse proxy. Below are minimal snippets you can adapt.

Nginx

server {
    listen 443 ssl;
    server_name localhost;

    ssl_certificate     /etc/nginx/certs/labca.crt;
    ssl_certificate_key /etc/nginx/certs/labca.key;

    location / {
        proxy_pass http://127.0.0.1:8000;
    }
}

Apache httpd

<VirtualHost *:443>
    ServerName localhost

    SSLCertificateFile      "/etc/apache2/certs/labca.crt"
    SSLCertificateKeyFile   "/etc/apache2/certs/labca.key"

    ProxyPass        "/" "http://127.0.0.1:8000/"
    ProxyPassReverse "/" "http://127.0.0.1:8000/"
</VirtualHost>

Common presets

Handy defaults you might reuse once Quick Certificate launches:

Internal services: CN=service.lab.local, SAN entries for service.lab.local and localhost.
Browser demos: 4096-bit RSA, 30-day validity, friendly name "Lab Demo CA".
Automation runners: PEM bundles stored with restricted file permissions (600).
